# Work Order: SSI Footer Injection for Faircamp Output (Stage Step)

## Goal
Add a site-wide footer to all generated static HTML pages produced by Faircamp, without modifying Faircamp itself.

Approach: post-process the final combined build in `stage/` by replacing (or appending to) the existing footer area with an SSI include hook, so the server can inject a shared footer fragment at request time.

This enables:
- One footer file to edit for the entire site
- SVG logo inclusion (inline SVG or referenced SVG)
- Future “nano-dashboard” enhancements (including optional JavaScript)

---

## Context
- Site build is generated by Faircamp (two installs) as static HTML.
- The final deployable artifact is the combined `stage/` directory (your “local mirror” of the remote site).
- `stage/` is rsynced to the server as the last step.
- We will test on real, live `stage/` output.

---

## Deliverables
1) `footerInclude.html` (SSI fragment)
2) `injectFooterSsiHook` (post-processing script run against `stage/`)
3) `nginxSsiConfigNotes.md` (minimal config notes and validation steps)
4) `rollbackPlan.md` (how to disable/undo quickly)

All filenames: camelCase, no spaces.

---

## Non-Goals (for now)
- No Faircamp fork, plugin, or template modifications.
- No JavaScript dashboard implementation yet (just make it possible).
- No full HTML re-templating. This is “gentle surgery”, not a transplant.

---

## Constraints / Assumptions
- Server is Nginx (likely) and can enable SSI.
- Some pages may already have a footer, some may not.
- Faircamp output may differ between “base” and “sotd” subsite. Injection must handle both.
- Must not break valid HTML or page rendering if SSI is disabled (graceful degradation).

---

# Work Orders

## WO-1: Inspect Stage HTML and Choose Injection Strategy
**Input:** a representative sample of real HTML files from `stage/`:
- Home page
- A track page
- An album/listing page
- A page inside the `sotd/` subtree

**Tasks:**
- Identify common patterns:
  - Do pages include `</body>` and `</html>` reliably?
  - Is there a `<footer>` element already?
  - Is there a consistent “last content block” before `</body>`?
- Decide the safest injection point:
  - Preferred: replace existing `<footer>...</footer>` if present.
  - Fallback: insert SSI hook immediately before `</body>`.

**Acceptance criteria:**
- A written decision in the doc: “We inject at X, with fallback Y.”

---

## WO-2: Define the SSI Footer Fragment (`footerInclude.html`)
**Tasks:**
- Create a single HTML fragment suitable for SSI inclusion:
  - Contains footer wrapper markup (e.g., `<footer class="siteFooter">...</footer>`)
  - Includes an SVG logo (Arch-style or your own mark) in one of two ways:
    - Option A: inline SVG in the fragment (simplest, one file)
    - Option B: `<img src="/assets/archLogo.svg" ...>` and store SVG in assets
  - Includes placeholders for:
    - Copyright
    - Links (e.g., Bandcamp, RSS, contact, etc.)
    - Optional future mini-dashboard container (e.g., `<div id="nanoDash"></div>`)

**Notes:**
- Keep it “dumb HTML” first. Styling can be minimal or inherited.
- If you want the SVG to be styleable via CSS, inline SVG is usually easiest.

**Acceptance criteria:**
- Fragment renders as a footer when included in a test HTML page.
- SVG displays correctly.

---

## WO-3: Implement Post-Processor to Inject SSI Hook Into Stage (`injectFooterSsiHook`)
**Tasks:**
- Write a script/tool that:
  - Walks `stage/` recursively
  - Targets `*.html` files
  - Skips known non-page artifacts if any (e.g., feeds, if they are `.html`-ish but shouldn’t be touched)
  - Injects this SSI line (exact form may vary by server config):
    - `<!--#include virtual="/include/footerInclude.html" -->`
- Injection logic:
  - If `<footer ...>` exists and is clearly the Faircamp footer, replace its contents or replace the whole element with the SSI include.
  - Otherwise, insert the SSI include right before `</body>`.
- Must create backups or be reversible:
  - Either write modified files to a parallel directory (e.g., `stageSsi/`)
  - Or write `*.bak` files (short-lived) and provide a revert step.

**Acceptance criteria:**
- Running the script modifies the intended set of pages.
- Pages remain valid HTML.
- No visible corruption, truncation, or duplicate footers.

---

## WO-4: Server Config Notes for SSI (Nginx) and Safety Switch
**Tasks:**
- Produce a short `nginxSsiConfigNotes.md` describing:
  - How to enable SSI for HTML (location block, `ssi on;`, any needed `ssi_types`)
  - Where the include fragment lives on the server:
    - e.g., `/srv/www/include/footerInclude.html` exposed as `/include/footerInclude.html`
  - Caching/compression considerations (brief)
  - A “kill switch”:
    - how to disable SSI quickly if needed, or how to remove the include file to force predictable failure behavior

**Acceptance criteria:**
- Notes include a simple verification checklist:
  - Confirm SSI is active by temporarily putting a distinctive token in the include
  - Confirm it appears on multiple pages

---

## WO-5: Integrate Into the Existing Deploy Pipeline
**Tasks:**
- Identify where your current staging occurs (the step that materializes the combined mirror in `stage/`).
- Insert the post-processing step after the two Faircamp outputs are merged into `stage/`, but before rsync upload.
- Ensure the include fragment is also deployed to the server path expected by SSI.

**Acceptance criteria:**
- A single “build + stage + inject + rsync” run results in live pages showing the shared footer.

---

# Testing Plan
1) Run Faircamp builds as usual.
2) Verify `stage/` looks normal before injection.
3) Run injection tool on `stage/` (or generate `stageSsi/`).
4) Open a few local files to confirm the SSI hook is inserted correctly.
5) Deploy to server.
6) Confirm SSI footer renders on:
   - root pages
   - `sotd/` pages
   - a deep nested track page

---

# Rollback Plan
- If injection wrote to a separate directory: revert by deploying original `stage/`.
- If injection modified in-place: restore from backups or re-run staging build to regenerate clean HTML.
- Disable SSI in Nginx as immediate stopgap if needed.
